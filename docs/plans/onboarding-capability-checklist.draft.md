작성: 2026-10-05 · 상태: **확정 (2026-10-05 owner 승인, 코드 미반영)**
관련: [onboarding-capability-input.md](onboarding-capability-input.md) A-1

## 0. 이 문서가 정하는 것
온보딩 STEP 2에서 사용자가 체크하는 **표시 항목**과, 체크 시 "본인 응답 보유(SELF_REPORTED)"로
저장할 **NCS 능력단위**의 연결표.

### 공통 규칙
1. 항목 하나는 능력단위 1개 이상에 연결된다. 체크하면 연결된 단위를 **모두** 보유로 저장한다. (승인)
2. 저장 시 `raw_text`는 **능력단위 공식 명칭**을 쓴다(이미 승인 별칭에 포함되어 있어
   `ConflictingEntityIdError`가 나지 않음). 새 별칭 추가는 없음.
3. 항목 문구는 **"해본 경험" + 기술명**으로 쓴다. 기술명을 댈 수 있는 항목은 문구 안에 기술명을 넣고,
   다른 기술도 해당되도록 "등"을 붙인다. 기술명이 자연스럽지 않은 항목(전공 과목, 기획, 문서화 등)은 경험 문장만 쓴다.
   기술명은 화면 표시용이며 판정·별칭에는 쓰지 않는다.
4. 학생이 스스로 판단하기 어려운 상위 설계·기획·운영 단위는 체크리스트에 넣지 않는다.
   해당 단위는 분석에서 계속 "부족"으로 남고, 필요하면 "내 정보"에서 입력한다. (승인)
5. 고위험 항목(D8: NCS 7수준 필수, A6: 90h)은 **그대로 유지**한다. 문구를 더 엄격하게 바꾸지 않는다. (승인)
6. 직무당 9~12개 항목. (승인)
7. 승인 초안 갱신으로 연결된 단위가 직무 요구 목록에서 사라지면 그 연결만 무시하고,
   연결이 모두 사라진 항목은 화면에서 숨긴다(fail-closed).

### 근거 데이터 대조 (완료)

연결된 단위는 모두 승인 초안에 존재. 필수/우대 구분 차이 2건(2001020219, 2001010506)은 아래 표에 반영.
