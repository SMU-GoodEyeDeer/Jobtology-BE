# Résumé scanner

Implemented on `feat/functionality-improvements` in the monolithic BE and the paired FE. It is available through **내 스펙 → 이력서에서 가져오기**, both during onboarding and later profile edits. It does not require a career goal.

The user uploads a document, optionally requests paragraph-by-paragraph AI extraction for a PDF, and reviews each suggestion against its source. A sanitized document preview and plain-text view support exact quotation highlights. The shared spec editor requires an explicit experience level for competency-bearing entries and confirmation before each save. Education and other information records do not require a level and never create competency credit. Only confirmed entries reach the existing versioned capability API. A new analysis applies eligible specs; an existing roadmap is not automatically replaced.

## API

All endpoints require the existing account session. POSTs require its CSRF token and trusted origin. Responses use `Cache-Control: no-store`.

- `GET /api/v1/me/resume/status`: actual runtime-supported `formats`, `max_bytes`, `max_pdf_pages: 20`, `parse_timeout_seconds`, `ai_available`, `ai_provider`, `ai_formats: ["pdf"]`, `ai_max_pdf_pages: 3`, `ai_max_paragraphs: 64`, `ai_max_characters: 12000`, `ai_concurrency: 4`, `retention: REQUEST_ONLY`.
- `POST /api/v1/me/resume/scan?format=docx[&occupation_id=...]`: raw binary request body (`application/octet-stream`), **no multipart or filename**. Returns document SHA-256, parser revision, text blocks, sanitized `preview_html` when available, actual PDF `page_count`, bounded keyword suggestions, warning codes and skipped PDF page numbers. No profile mutation and no AI call.
- `POST /api/v1/me/resume/analyze?format=pdf&ai_consent=true[&occupation_id=...]`: raw PDF body. Rejects non-PDF input, missing consent, more than three physical pages, or excessive text/paragraphs before any model call. Uses the existing configured LLM/provider (currently Luna/ChatGPT OAuth); no Decisions classifier or new model/billing configuration. Returns `application/x-ndjson` with `X-Accel-Buffering: no`. Parsing/validation errors before streaming retain normal JSON HTTP error statuses.
- `POST /api/v1/me/resume/interpret`: JSON `{text, occupation_id?}` with a selected, user-reviewed passage of at most 2,000 Unicode code points. Explicit opt-in only; it calls the existing configured LLM client. Returns canonical skill IDs plus exact source quotes and validated code-point offsets. Invalid IDs/quotes/spans are discarded, with `rejected_count`.

The AI stream consists of a `scan` event containing the parsed document (initially no suggestions), then `paragraph` events as calls complete, and a final `done` event. Paragraph events include `block_id`, `completed`, `total`, `suggestions`, `rejected_count`, and nullable `error_code`. Each suggestion contains its category, title, exact quote/span, recognized competencies and a `fields` dictionary copied verbatim from the quote. `done` includes `failed`, `rejected_count`, `omitted_count`, and `timed_out`. A terminal `error` event contains the ordinary safe error envelope. Treat EOF without `done` as interrupted and keep already received suggestions for manual review.

The endpoints share the existing PostgreSQL account quota with chat (20 requests/minute/account); an AI import consumes one quota request per document. Logout/login does not reset it. Parsing and AI processing also allow one active document per account and two total per BE filesystem, shared across web workers using file locks. These slots do not coordinate separate hosts; each host has its own capacity limit.

## Formats and bounds

DOCX and HWPX use Python parsers. Text PDF requires Java 11+ and the bundled ODL converter; legacy HWP requires Java 25/JPype and its bundled converter; legacy DOC requires .NET 8 and its bundle. The status endpoint only advertises discovered runtimes. The monolith Railpack configuration installs Java 25/.NET 8. Runtime discovery does not guarantee every template can be read.

- Upload: 10 MiB, 30-second streaming deadline, magic/container checks.
- PDF: ordinary scanning accepts up to **20 actual pages**; AI import accepts up to **three actual pages**. The relevant limit is checked with the PDF reader before native extraction or model calls; reject encrypted input. Image-only/unreadable pages show `OCR_REQUIRED` and page numbers; **OCR is not implemented**. AI import accepts PDF only. Other formats remain available for non-AI scanning without a page-count limit, because processor page-layout counts are not a guaranteed physical page count; file/text/process limits still apply.
- Archives: at most 1,000 members / 40 MiB expanded / 15 MiB per member / 200:1 compression ratio; reject path traversal, encryption, macro bundles, XML DTD/entity declarations (including UTF-16/32 NUL interleaving).
- Child parser: 60-second wall deadline, 45 CPU seconds per process, 4 GiB address-space limit per process, 32 MiB output-file limit, 128 open descriptors, no core dump. Native heaps are restricted. The whole process group is killed on completion, timeout or client cancellation. An independent child alarm also covers a web worker crash.
- Results: at most 50,000 text code points / 500 blocks / 1,800 code points per block / 200 suggestions; truncation is visible. Only known PDF physical page numbers are shown; DOCX/HWPX pages are not invented.
- AI: at most **64 blocks and 12,000 text code points**, four concurrent requests per document (eight across two host slots), one structured extraction call per paragraph block, five entries per call, 200 suggestions total. Long paragraphs are split at the 1,800-code-point block boundary. Each call has a 30-second deadline; the AI phase has a 120-second deadline. There are no automatic retries. Failed/timed-out paragraphs do not discard successful results. Cancelling closes pending requests and releases the slot, though provider work already accepted may have consumed usage.

Synthetic Korean DOCX (including tables/hidden styles), HWPX, text PDF and image-only PDF are exercised in tests. HWP/DOC native assets/startup are covered by the existing installed-wheel smoke checks; real legacy résumé-template accuracy is not established by those checks.

## Temporary data and preview

The source filename is never sent. The server writes to a private directory under the system temporary directory with an opaque generated name, launches the processor in a separate process, returns bounded JSON and removes all files in `finally`. No original file, IR, preview or import job is added to the database. Active locks prevent crash cleanup from deleting live requests. A lifespan sweeper runs every minute and removes unlocked leftovers older than 15 minutes, including after a restart. There are only three reusable capacity lock files, not a growing file per account/session. Normal cancellation disconnects stop processing and erase the request directory.

The child receives a restricted environment without database/LLM credentials. These are process/resource boundaries, not a full OS sandbox or malware scanner; parsing remains part of the trusted BE deployment. Keep parser and native runtime dependencies patched.

The source file is removed before AI extraction starts. The FE holds returned text/preview only in component memory. Finish, navigation, logout/account deletion and component unmount clear that preview; no document content enters URLs, analytics, localStorage or console logs. Confirmed spec quotes/fields are ordinary account data and are removed by existing account deletion. Original files are not retained for future previews.

The processor's HTML is reduced to structural tags, validated source-anchor IDs and a small enumerated style subset. Scripts, external resources, source links, event handlers and arbitrary CSS are removed. The fragment is displayed in a scripts-disabled sandbox iframe with CSP blocking network access. Parent-controlled highlighting uses the same Unicode quotation offsets as the text view; ambiguous or missing anchors show a fallback notice instead of guessing. Preview rendering failure preserves readable text. Explicit DOCX hidden/deleted runs and hidden character/paragraph styles are excluded. Extraction can still differ from visible layout and reading order; the user must review it.

## Meaning of suggestions

Literal matching uses NCS/O*NET catalog labels/aliases and ASCII token boundaries (JavaScript is not Java). Suggestions are grouped per text block, not one spec per keyword. A few explicitly written language-test scores are parsed; no dates, issuer, degree, credential validity or proficiency are invented. Year/month dates remain in the quotation for user review, rather than becoming invented day-level dates. Header context can suggest a category, but users can change it. Bare headings do not count as qualifications.

Keyword occurrences may describe aspirations, negations, third-party experience or job requirements. They are **observations for review**, not competency credit. The AI prompt explicitly excludes those cases, but users still review every suggestion. O*NET IDs remain distinct and do not imply an NCS crosswalk.

Full-document AI extraction requires its own consent checkbox before upload. Each request contains the current paragraph and up to 360 code points of previous-paragraph context, alongside bounded catalog choices. It categorizes and extracts fields in the same structured response, preserving multiple records and unmatched education/experience. Obvious email/phone patterns are masked on the server. Names, addresses and confidential work details are not comprehensively de-identified: the UI asks users to review the file before upload. The existing selected-passage fallback separately displays an editable outgoing passage and requires consent. The configured client sends `store: false`; this does not change the provider's independent retention terms. No live résumés or paid model calls are part of development tests; real-model accuracy remains to be evaluated.

Confirmed specs use `details.source: DOCUMENT_IMPORT` and a strict `document_evidence` object: document fingerprint, parser revision, block ID/text hash, exact original quote, half-open Unicode code-point span and method (`KEYWORD`, `AI_ASSISTED`, `SELECTED_TEXT`). `details.imported_fields` retains verbatim extracted fields, including partial dates, and requires values found in that source quote. The editor only pre-fills date controls when a complete valid day is explicit; it never invents the first day of a month. This is user-supplied provenance, **not cryptographic verification**. No arbitrary internal completion fields or verified-credential flags are accepted. Edited/redacted AI quotes are re-anchored only when exact and unambiguous; repeated spans retain explicit offsets when the original passage is unchanged. The FE uses code-point slicing, not UTF-16 offsets.

Experience level is mandatory for competency-bearing categories and never inferred from a document. The existing modeled planning weights and evidence rules apply only after confirmation. Duplicate evidence is not summed. `education` and `other` categories are information records with nullable proficiency and no competency IDs/credit. School, degree and major are saved as reviewed spec details, without automatically changing account education/profile fields. The current version does not merge existing specs, perform OCR, or verify credentials.

## Deployment

No SQL migration or new secret is needed. Deploy matching BE then FE versions; the existing LLM configuration enables extraction and selected-passage interpretation. Ensure reverse-proxy idle timeouts allow the initial parser phase and streamed AI results. The temporary directory must be writable by the BE user and private to that service. The normal Java 25/.NET 8 image configuration must be included to advertise native formats. This branch has not been deployed by the implementation task.
